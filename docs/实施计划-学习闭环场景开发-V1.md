# 实施计划：学习闭环场景开发（V1）

## 1. 目标
基于 `docs/PRD-教科书级自主探索学习闭环-V1.md`，将四个标杆场景拆解为可直接开发、可验收、可运营复用的任务计划。

四个标杆场景：
1. 数学：二次函数图像与参数变换
2. 化学：化学平衡与勒夏特列原理
3. 物理：串并联电路与欧姆定律
4. 生物：酶活性与温度/pH影响

---

## 2. 开发策略

## 2.1 总体原则
- 先做“模板场景”再复制扩展，减少重复开发和返工。
- 每个场景必须包含：步骤导航、交互操作、练习判分、AI反馈、总结卡。
- 优先保证“闭环可走通”，再做视觉增强和复杂动画。
- 视觉一致性优先：保持深色Blender主风格，题目讲解采用局部黑板面板，不做全局白底切换。
- 所有面板/弹窗必须有关闭按钮，移动端触摸区不小于 44x44。

## 2.2 本期顺序（建议）
1. 模板场景（数学）先跑通闭环
2. 复用模板接入物理
3. 复用模板接入化学
4. 复用模板接入生物

## 4. 通用模块拆解（先做一次，四场景复用）

## 4.1 学习引擎 `js/learning-engine.js`
职责：
- 管理步骤状态（stepIndex、已完成步骤）
- 管理练习状态（答题记录、得分、错因）
- 计算掌握度分数（题目分+过程分+探索分）
- 生成总结卡数据（分数、薄弱点、建议）

接口建议：
- `createSession(sceneId)`
- `completeStep(sceneId, stepId)`
- `submitAnswer(sceneId, questionId, answer)`
- `getSummary(sceneId)`

## 4.2 学习路径配置 `data/learning-path-config.js`
每个场景配置：
- `steps`（步骤标题、目标、操作提示）
- `exploreActions`（必须完成的关键交互）
- `completionRules`（闭环完成条件）

建议字段补充：
- `sceneType`（`concept` / `problem`）
- `guideMode`（`immersive` / `blackboard` / `mixed`）
- `uiSafety`（关闭按钮可见性、移动端触控检查）

## 4.3 题库配置 `data/quiz-bank.js`
每个场景至少3题：
- `basic`（基础）
- `application`（应用）
- `transfer`（迁移）

每题字段建议：
- `id`
- `type`（single/multi/input/drag）
- `question`
- `options`
- `correctAnswer`
- `errorTags`（错因标签）
- `feedbackTemplate`

## 5. 场景开发任务分解

## 5.1 场景A：二次函数（模板场景）
目标：跑通“完整闭环模板”，成为其余三场景母版。

任务：
1. 实现场景基础渲染与参数交互（a,b,c滑块）
2. 完成3步导航与步骤锁定逻辑
3. 接入黑板式步骤讲解面板（局部浮层，非全局白底）
4. 接入题库（3题）与即时判分
5. 接入AI反馈（错因+下一步操作建议）
6. 输出总结卡（掌握度+薄弱点）

验收：
- 不看外部资料可完成学习闭环
- 3题答完后可得到结构化总结

## 5.2 场景B：串并联电路
任务：
1. 拖拽式元件连接（简化版）
2. 实时显示U/I/R和安全状态
3. 三步学习路径与3道题接入
4. 错误连线高亮反馈

## 5.3 场景C：化学平衡
任务：
1. 粒子层可视化 + 浓度/温度/压强控制
2. 平衡移动方向可视化提示
3. 三步学习路径与3道题接入
4. 三段式反馈（现象/原因/应用）

## 5.4 场景D：酶活性
任务：
1. 温度/pH/底物浓度交互
2. 双曲线联动（速率-温度、速率-pH）
3. 三步学习路径与3道题接入
4. 变性与不可逆提示反馈

## 6. 运营联动任务（每个场景都要交付）
1. 30秒演示脚本（场景亮点）
2. 3分钟教学讲解稿（步骤导学）
3. 互动练习题帖（可用于社媒）
4. 场景封面图（统一视觉模板）

---

## 7. DoD（开发完成定义）
每个场景只有同时满足以下条件才算完成：
1. 步骤、交互、练习、反馈、总结五模块全部可用。
2. 至少3道题可判分，错因可解释。
3. 移动端与PC端均可走完整闭环（不阻断）。
4. 无高优先级缺陷（白屏、按钮不可达、流程卡死）。
5. 具备1份运营素材（短演示或题帖）可对外发布。
6. 模态框/面板/弹窗全部带关闭按钮，且移动端触控区满足44x44。
7. 新场景视觉风格与现有深色体系一致，不出现UI风格割裂。

- D10：运营素材制作与发布

---

## 9. 风险与预案
- 风险1：四场景并行导致质量不均
  - 预案：先以模板场景验收通过后再复制
- 风险2：题库判分规则不稳定
  - 预案：V1仅使用可解释题型（选择、填空、参数目标）
- 风险3：移动端交互复杂
  - 预案：移动端优先保留核心流程，复杂操作用“自动演示按钮”替代
