## ⚠️ 场景类型判断（必读）

> **重要**：收到用户3D场景需求后，必须先判断场景类型，选择正确的开发规范！

### 两种规范的区别

| 对比维度           | 本规范（3D场景开发规范）              | 题目可视化规范                 |
| ------------------ | ------------------------------------- | ------------------------------ |
| **核心目的** | 原理/概念/现象的可视化理解            | 帮助学生学习解题方法           |
| **内容重点** | 动态演示、探索发现                    | 解题步骤、思路讲解             |
| **教学形式** | 自由探索、参数调节                    | 黑板式教学、分步引导           |
| **典型场景** | 电磁感应、DNA结构、行星运动、排序算法 | 几何证明、力学计算、化学方程式 |
| **交互目标** | 理解"为什么"                          | 掌握"怎么做"                   |
| **视觉风格** | 深色Blender风格                       | 纯白/浅色教室风格              |
| **参考文档** | 本文档                                | `docs/题目可视化规范.md`     |

### 判断流程

```
用户需求
    ↓
是否包含明确的"题目"或"求解"要求？
    ↓
    ├─ 是（题目场景）
    │   ├─ 有具体题目条件（已知A、B、求C）
    │   ├─ 需要求解/证明/计算
    │   ├─ 需要展示解题步骤
    │   ├─ 目的是教会学生"做题"
    │   └─ → 使用【题目可视化规范】
    │
    └─ 否（概念场景）
        ├─ 展示原理/现象/概念
        ├─ 自由探索为主
        ├─ 无明确解题要求
        ├─ 目的是帮助学生"理解"
        └─ → 使用【本规范】
```

## 🎯 核心教学理念

### 设计哲学：让学习变成探索

```
传统教学：看 → 听 → 记
沉浸式教学：探索 → 操作 → 发现 → 理解 → 应用
```

### 教学体验金字塔模型

```
                    ┌─────────────────────┐
                    │   5. 应用与创造       │  ← 学生改参数、做推导
                   ┌┴─────────────────────┴┐
                   │  4. 深度理解与分析    │  ← 点击查看公式、原理
                  ┌┴───────────────────────┴┐
                  │   3. 互动操作体验      │  ← 拖拽、点击、改值
                 ┌┴─────────────────────────┴┐
                 │    2. 观察感知          │  ← 3D动画、动态过程
                ┌┴───────────────────────────┴┐
                │  1. 引入与激发          │  ← 问题情景、好奇心
                └──────────────────────────┘
```

### 五大必须原则

| 原则               | 要求                       | 实现方式                             |
| ------------------ | -------------------------- | ------------------------------------ |
| **正确性**   | 物理原理100%科学           | 公式推导、单位换算、方向判断都要验证 |
| **可操作性** | 学生主动探索而非被动观看   | 至少3个交互点、参数可调、结果可观察  |
| **清晰性**   | 学习目标明确，过程清晰     | 有引导、有反馈、有总结               |
| **沉浸性**   | 3D体验增强理解而非分散注意 | 场景为主、文字为辅、动画有目的       |
| **即时反馈** | 操作后立即看到结果         | 动画、数值变化、声音提示             |

### 抽象概念可视化设计原则

对于**公理、定理、思维实验**等抽象概念，必须遵循以下设计流程：

```
抽象概念 → 可视化模型 → 步骤引导 → 可操作验证 → 深化理解
```

#### 设计要素

| 要素               | 要求                    | 示例                               |
| ------------------ | ----------------------- | ---------------------------------- |
| **可视化**   | 用3D图形表达抽象概念    | 薛定谔的猫用半透明叠加态表示       |
| **步骤引导** | 分阶段展示，循序渐进    | 量子纠缠：制备态→分离→测量→坍缩 |
| **可解释**   | 每个步骤配文字/公式说明 | 点击显示数学表达式                 |
| **可操作**   | 用户参与关键操作        | 点击"测量"触发波函数坍缩           |

#### 典型示例

```javascript
// 薛定谔的猫 - 抽象概念可视化
class SchrodingerCatScene {
    // 步骤1：展示实验装置（引入）
    showSetup() {
        this.showGuide('🔬 盒子里有：放射性原子 + 毒气装置 + 猫');
    }
  
    // 步骤2：解释叠加态（可视化）
    showSuperposition() {
        // 用半透明叠加显示"活猫"+"死猫"同时存在
        this.aliveCat.material.opacity = 0.5;
        this.deadCat.material.opacity = 0.5;
        this.showGuide('😺😿 观测前，猫处于"活+死"的叠加态！');
    }
  
    // 步骤3：用户操作观测（可操作）
    onBoxClick() {
        // 用户点击触发"观测"
        const isAlive = Math.random() > 0.5;
        this.collapseWaveFunction(isAlive);
        this.showGuide(isAlive ? '😺 猫活着！' : '😿 猫死了！');
    }
  
    // 步骤4：解释波函数坍缩（可解释）
    showExplanation() {
        this.showInfoPanel({
            name: '波函数坍缩',
            description: `
                <p>观测前：|ψ⟩ = α|活⟩ + β|死⟩</p>
                <p>观测后：坍缩为确定状态</p>
                <p>这就是量子测量问题的核心！</p>
            `
        });
    }
}
```

### 同类场景合并策略

对于**概念相似、单独较简单**的场景，应该**合理合并**以提高教学效率：

#### 合并原则

| 原则               | 说明             | 示例                           |
| ------------------ | ---------------- | ------------------------------ |
| **主题统一** | 属于同一知识体系 | 多种排序算法 → 排序算法可视化 |
| **对比教学** | 合并后能形成对比 | A*/BFS/DFS → 迷宫寻路对比     |
| **渐进复杂** | 从简单到复杂排列 | 0D→1D→2D→3D→4D → 维度演化 |
| **避免冗余** | 共享UI/环境/交互 | 复用控制面板和场景基础         |

#### 合并示例

```javascript
// ❌ 拆分为多个简单场景（不推荐）
class BubbleSortScene { ... }
class QuickSortScene { ... }
class MergeSortScene { ... }

// ✅ 合并为一个综合场景（推荐）
class SortingScene {
    constructor() {
        this.algorithms = {
            bubble: { name: '冒泡排序', complexity: 'O(n²)' },
            quick: { name: '快速排序', complexity: 'O(n log n)' },
            merge: { name: '归并排序', complexity: 'O(n log n)' },
            insertion: { name: '插入排序', complexity: 'O(n²)' },
            selection: { name: '选择排序', complexity: 'O(n²)' }
        };
    }
  
    setupUI() {
        // 算法选择按钮组 - 切换不同算法演示
        controlsDiv.innerHTML = `
            <div class="algo-buttons">
                ${Object.entries(this.algorithms).map(([key, algo]) => 
                    `<button class="algo-btn" data-algo="${key}">${algo.name}</button>`
                ).join('')}
            </div>
        `;
    }
  
    // 教学价值：直观对比不同算法效率
    runComparison() {
        // 同时运行多个算法，对比交换次数和时间
    }
}
```

#### 适合合并的场景类型

| 类型               | 合并方式         | 教学价值           |
| ------------------ | ---------------- | ------------------ |
| **算法类**   | 多算法对比       | 效率差异、思想对比 |
| **物理定律** | 相关定律统一展示 | 因果关系、公式联系 |
| **维度演化** | 从低维到高维     | 递进规律、抽象理解 |
| **生物结构** | 同一系统不同层级 | 层次关系、功能联系 |

#### 不适合合并的情况

- 概念差异大的场景（如：单摆 vs DNA）
- 复杂度都很高的场景（会导致页面卡顿）
- 操作方式完全不同的场景（会让用户困惑）
- 教学目标冲突的场景（会分散注意力）

### 反面列表（要避免的设计陷阱）

❌ **常见错误：**

- 场景华丽但原理错误
- 3D动画超过4秒用户失去耐心
- 过多文字遮挡3D场景
- 点击后无反馈，用户不知道发生了什么
- 参数改不了，只能看
- 没有重置功能，错过了就得重新加载
- 移动端完全无法使用
- 单一视角固定，看不全场景
- **抽象概念没有可视化，只有文字说明**
- **简单同类场景分散开发，缺乏对比**

```javascript
const requirementAnalysis = {

        "是否有复杂的运动过程？",
        "是否需要参数调节？",

    // 3. 交互需求分析
    interactionNeeds: [
        "用户主要交互方式是什么？",
```

### 信息流设计模式

```
用户操作
    ↓
交互处理层 (handleClick/handleDrag)
    ↓
业务逻辑层 (updateParams/calculateValues)
    ↓
数据更新层 (updateModelPositions/updateLabels)
    ↓
3D 渲染层 (animate)
    ↓
UI 反馈层 (updateInfoPanel/showGuide)
    ↓
用户感知结果
```

```javascript
            new THREE.SphereGeometry(1, 16, 16),
            this.sharedMaterials.primaryMesh
        );
        lod.addLevel(lowPoly, 50);
  
        this.mainGroup.add(lod);
    }
```

### Q: 如何实时显示参数数值变化？

```javascript
updateParameterDisplay(name, value) {
    const label = document.getElementById(`param-${name}`);
    if (label) {
        gsap.to({ val: parseFloat(label.textContent) }, {
            val: value,
            duration: 0.3,
            onUpdate: function() {
                label.textContent = this.targets()[0].val.toFixed(2);
            }
        });
    }
}
```

### 📋 按钮交互规范

每个场景的按钮必须**点击有反馈**：

```javascript
// 标准按钮交互模板
bindUIEvents() {
    // 1. 视觉反馈：按钮状态变化
    document.getElementById('btn-play')?.addEventListener('click', () => {
        this.togglePlay();
        // 按钮图标切换
        const btn = document.getElementById('btn-play');
        btn.innerHTML = this.isPlaying 
            ? '<i class="fas fa-pause"></i> 暂停' 
            : '<i class="fas fa-play"></i> 播放';
    });
  
    // 2. 场景反馈：触发动画或状态变化
    document.getElementById('btn-action')?.addEventListener('click', () => {
        this.executeAction();
        // 显示操作提示
        this.showGuide('✅ 操作已执行！');
    });
  
    // 3. 视觉反馈：高亮相关部件
    document.getElementById('btn-highlight')?.addEventListener('click', () => {
        this.highlightKeyComponents();
        // 缩放动画
        gsap.to(this.keyPart.scale, {
            x: 1.2, y: 1.2, z: 1.2,
            duration: 0.2,
            yoyo: true,
            repeat: 1
        });
    });
}
```

## 📝 附录：用户需求提示词参考(用户没说也主动把用户的场景需求带入理解)

用一个炫酷动态3D可交互场景呈现【用户需求的场景】，场景重要部件都要可解释，鼠标经过有优雅的中文弹框解释，可自动关闭，场景要实现3D动态可交互，比如旋转，放大缩小等等操作，点击部件时候摄像头应跟随，并且可以操作任何角度以及视觉移动到任何位置。目的是使得初中生都能动手学习以及理解，注意场景要清晰可见，注意部件的可读性，界面元素不要遮挡主题。

场景主体界面参考3D建模软件(Blender风格视图)那种感觉做，3D场景在网格平面上方那种感觉。

*注意每一个场景的实现都必须遵守规则，合理规划，包含不限于场景，部件，按钮，等等。一个一个来，每一个都要深度仔细思考规划出最佳方案，然后一步一步实施实现。*
